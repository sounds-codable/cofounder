# 小程序编译发布与多端架构实施说明

## 目标

- 在不影响现有网页端（`client/`，Next.js）的前提下，提供微信小程序端。
- 延续架构方向：**一套后端服务，多套前端按端形态独立演进**。

## 当前实现

### 新版原生小程序（`client_xcx/`）— 当前主力

- **框架**：微信官方原生开发（WXML + WXSS + JS），无第三方框架依赖。
- **API 后台**：与网页版共用 `https://cofounder.icu/api`，在 `utils/api.js` 中统一封装。
- **登录方式**：邮箱验证码登录/注册，不区分身份角色，与网页版一致。
- **UI 风格**：配色、圆角、字体等与新版网页版 (`client/`) 保持一致。

### 旧版 Taro 小程序（`archive/client/`）— 已归档

- 使用 Taro 4.x + React 构建，保留在 `archive/` 目录供参考。
- 不再作为主力开发和发布版本。

### 后端统一

- `server/`（NestJS）继续作为 Web/小程序共用 API 服务。

## `client_xcx/` 目录结构

```text
client_xcx/
├── app.js                  # 小程序入口，全局状态管理
├── app.json                # 小程序配置（页面路由、tabBar、窗口）
├── app.wxss                # 全局样式（配色、按钮、卡片、表单等）
├── project.config.json     # 微信开发者工具项目配置
├── sitemap.json            # 小程序站点地图
├── assets/                 # tabBar 图标
│   ├── tab-projects.png / tab-projects-active.png
│   ├── tab-developers.png / tab-developers-active.png
│   ├── tab-requests.png / tab-requests-active.png
│   └── tab-profile.png / tab-profile-active.png
├── utils/
│   ├── api.js              # 所有后端 API 请求封装
│   └── util.js             # 工具函数（时间格式化、状态映射、登录检查等）
└── pages/
    ├── projects/           # 项目库（TabBar 页）— 列表/筛选/收藏/点赞
    ├── developers/         # 程序员（TabBar 页）— 列表/筛选/收藏/点赞
    ├── requests/           # 请求中心（TabBar 页）— 收到/发出的请求
    ├── profile/            # 我的（TabBar 页）— 个人信息/联系方式/退出
    ├── login/              # 登录/注册（邮箱验证码）
    ├── card-detail/        # 卡片详情 — 公开信息/请求流程/联系方式交换
    ├── publish/            # 发布项目/登记程序员 — 创建/编辑卡片
    └── detail-profile/     # 完善详细资料 — 了解详情请求时填写
```

## 页面与功能对应

| 小程序页面 | 对应网页版路由 | 功能说明 |
|---|---|---|
| `pages/projects/` | `/projects` | 项目库列表，支持城市筛选、我发布的/我收藏的视图切换，点赞和收藏 |
| `pages/developers/` | `/developers` | 程序员列表，功能与项目库对称 |
| `pages/requests/` | `/requests` | 请求中心，分「收到的」和「发出的」两个 Tab，支持批准/拒绝/交换联系方式 |
| `pages/profile/` | 多个页面整合 | 我的中心，含昵称设置、联系方式管理、卡片管理、详细资料入口 |
| `pages/login/` | `/login` | 邮箱验证码登录/注册，支持邀请码 |
| `pages/card-detail/` | `/[role]/[slug]` | 卡片详情页，含请求状态机、联系方式交换完整流程 |
| `pages/publish/` | `CardPublishForm` | 发布新项目或登记为程序员，支持编辑已有卡片 |
| `pages/detail-profile/` | `/onboarding/detail` | 完善详细资料（自我介绍、教育、经验、项目详情），已填写可回填编辑 |

## API 接入说明

- API 基址：`https://cofounder.icu/api`，硬编码在 `utils/api.js` 顶部。
- Token 存储：使用 `wx.setStorageSync('access_token')` 存储 JWT。
- 请求头统一携带 `Authorization: Bearer <token>`。
- 内容风控：后端返回 `RISK_REVIEW_REQUIRED` 时，弹出 `wx.showModal` 确认后带 `riskConfirmed: true` 重试。
- 401 处理：自动清除 token 并跳转登录页。

## 小程序本地开发步骤

### 1) 导入项目

- 打开微信开发者工具
- 选择「导入项目」
- 项目目录选择：`client_xcx/`（仓库根目录下）
- 填入正式 AppID（或使用测试号）

### 2) 配置 AppID

编辑 `client_xcx/project.config.json`：

- 将 `appid` 改为你的小程序正式 AppID。

### 3) 配置合法域名

在微信公众平台 → 开发管理 → 开发设置，配置：

- `request 合法域名`：`https://cofounder.icu`

注意：

- 必须为 HTTPS
- 域名证书必须有效
- 本地开发时可在开发者工具中勾选「不校验合法域名」

### 4) 预览与调试

- 在开发者工具中直接预览
- 使用真机扫码预览进行真机调试

## 发布流程

### 1) 上传

- 在微信开发者工具中点击「上传」
- 填写版本号和项目备注

### 2) 提审

- 登录微信公众平台
- 在「版本管理」中提交体验版
- 设置体验成员测试
- 提交审核

### 3) 发布

- 审核通过后在公众平台点击「发布」

## 架构思路结论

1. **后端统一**使用 NestJS（当前已落地，继续演进）。
2. **Web 前端**使用 Next.js（`client/`，已上线，独立发布节奏）。
3. **小程序前端**使用微信原生开发（`client_xcx/`，本次新建，轻量无依赖）。
4. **旧版 Taro 小程序**保留在 `archive/client/` 供参考。
5. **App 端**后续按团队能力选择 React Native 或 Flutter，仍复用同一后端。
