# 小程序编译发布与多端架构实施说明

## 目标

- 在不影响现有网页端（`client/`，Next.js）的前提下，恢复并发布微信小程序端（`archive/client/`，Taro）。
- 延续你提出的架构方向：**一套后端服务，多套前端按端形态独立演进**。

## 当前实现（已落地）

- **后端统一**：`server/`（NestJS）继续作为 Web/小程序共用 API 服务。
- **Web 前端**：`client/`（Next.js）保持现状，不做破坏性改动。
- **小程序前端**：`archive/client/`（Taro）用于微信小程序构建与发布。
- **API 基址适配**（已实现）：
  - H5 走相对路径 `/api`（适配代理）。
  - 小程序优先读取 `TARO_APP_API_BASE`，构建时注入后拼接 `/api`。
  - 未配置时，小程序开发默认使用 `http://localhost:3010/api`（仅本地调试）。

## 推荐的长期目录演进（可选）

后续可以把 `archive/client/` 升级成正式的多端目录，例如：

```text
apps/
  web/         # Next.js
  miniapp/     # Taro Weapp
  app/         # React Native / Flutter（择一）
server/        # NestJS
```

该步骤不是本次发布前置条件，建议在小程序首发后进行。

## 小程序本地编译步骤

### 1) 安装依赖

在仓库根目录执行：

```bash
npm run miniapp:install
```

### 2) 本地开发编译（微信开发者工具预览）

```bash
npm run miniapp:dev
```

说明：

- 上述命令会注入 `TARO_APP_API_BASE=http://localhost:3010`。
- 若后端地址不同，请手动覆盖：

```bash
TARO_APP_API_BASE=http://127.0.0.1:3010 npm run dev:weapp --prefix archive/client
```

### 3) 生产构建

必须提供可被微信访问的 HTTPS 域名（不带 `/api`）：

```bash
TARO_APP_API_BASE=https://api.your-domain.com npm run miniapp:build
```

构建产物目录：

- `archive/client/dist/`

## 微信开发者工具发布流程

### 1) 配置 AppID

编辑 `archive/client/project.config.json`：

- 将 `appid` 从 `touristappid` 改为你的小程序正式 AppID。

### 2) 导入项目

- 打开微信开发者工具
- 选择“导入项目”
- 项目目录选择：`archive/client`
- 开发目录会自动识别为：`dist`

### 3) 配置合法域名

在微信公众平台 -> 开发管理 -> 开发设置，配置：

- `request 合法域名`：`https://api.your-domain.com`

注意：

- 必须为 HTTPS
- 不能使用 `localhost` / `127.0.0.1`
- 域名证书必须有效

### 4) 上传与提审

- 开发者工具中点击“上传”
- 在公众平台提交体验版/审核版
- 审核通过后发布

## 线上联调检查清单

- 后端 CORS、鉴权、路由前缀统一为 `/api`。
- 小程序构建时已注入 `TARO_APP_API_BASE`，请求 URL 为：
  - `https://api.your-domain.com/api/...`
- 登录、列表、详情、提交表单各主链路完成真机回归。
- 关注微信环境差异：网络超时、Token 过期重登、页面栈跳转限制。

## 你当前架构思路的建议结论

你的思路正确，建议按以下路线执行：

1. 后端统一使用 NestJS（当前已落地，继续演进即可）。
2. Web 使用 Next.js（当前已上线，保持独立发布节奏）。
3. 小程序使用 Taro（本次已打通构建发布流程）。
4. App 端后续按团队能力二选一：React Native 或 Flutter，仍复用同一后端。
