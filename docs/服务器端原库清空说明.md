# 服务器端原库清空说明

按当前重构要求：

- **本地开发数据库名使用 `cofounder_new`**
- **服务器端数据库名保持原名不变**
- **服务器端需要清空原有业务数据**

## 1. 建议时机

建议在新版本准备上线前执行，而不是现在立即执行。

原因：

- 当前还在重构阶段
- 新表结构、迁移方式、初始化数据策略还会继续调整
- 过早清空生产数据库没有意义，还可能影响旧系统排查

## 2. 推荐处理方式

推荐只在正式切换前执行以下其中一种：

### 方式 A：删除原有业务表，再由新后端自动建表

适用于：

- 新库结构与旧库结构差异很大
- 开发阶段临时使用 `TYPEORM_SYNCHRONIZE=true`

### 方式 B：保留数据库名，手工清空业务数据与旧表结构，再执行迁移

适用于：

- 上线时希望走更可控的 SQL / migration 方案

## 3. 当前建议

当前仓库阶段建议：

- 本地先使用 `cofounder_new` 完成新版本开发与联调
- 服务器端等到新版本联调稳定后，再补一份正式的生产清库与初始化脚本

也就是说，这次先把：

- 新项目结构
- 新前后端骨架
- 本地数据库文档
- 部署兼容性

先落下来；生产清库脚本放到下一阶段单独做，会更稳妥。
