## 2. 你需要在服务器上配合执行的操作

> 以下命令在服务器执行；执行前先备份线上配置。

### 2.1 更新后端环境变量（必须）

编辑：`/var/www/www.cofounder.icu/shared/server/.env`

至少确认包含：

```env
NODE_ENV=production
JWT_SECRET=请替换为高强度随机密钥

CORS_ALLOWED_ORIGINS=https://cofounder.icu,https://www.cofounder.icu
TRUST_PROXY=true

AUTH_SEND_CODE_INTERVAL_SECONDS=60
AUTH_SEND_CODE_MAX_PER_EMAIL_PER_HOUR=8
AUTH_SEND_CODE_MAX_PER_IP_PER_HOUR=20
AUTH_VERIFY_MAX_FAILURES=6
AUTH_VERIFY_LOCK_MINUTES=30
```

### 2.2 下发并启用 Nginx 配置（必须）

使用项目脚本（推荐）：

```bash
./scripts/init-server.sh
```

或手动：

```bash
sudo cp /tmp/cofounder.icu.nginx.conf /etc/nginx/sites-available/cofounder.icu
sudo ln -sf /etc/nginx/sites-available/cofounder.icu /etc/nginx/sites-enabled/cofounder.icu
sudo nginx -t
sudo systemctl reload nginx
```

### 2.3 重启后端（必须）

```bash
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl restart cofounder-backend
```

### 2.4 验证项（必须）

1) HTTPS 与域名跳转
- `http://cofounder.icu` 应 301 到 `https://cofounder.icu`
- `http://www.cofounder.icu` 应 301 到 `https://cofounder.icu`
- `https://www.cofounder.icu` 应 301 到 `https://cofounder.icu`

2) 安全头
- 响应中应看到：
  - `Strict-Transport-Security`（HTTPS）
  - `X-Content-Type-Options`
  - `X-Frame-Options`
  - `Referrer-Policy`
  - `Permissions-Policy`

3) 验证码限流
- 同邮箱 60 秒内重复请求，应返回 429。
- 连续输错验证码达到阈值，应返回锁定提示（429）。

4) 服务启动保护
- 若 `JWT_SECRET` 缺失或是默认值，后端应拒绝启动（这是预期行为）。

### 4.4 全站输入防护覆盖检查结论（当前版本）

1) 已覆盖的核心防护
- 全局请求校验：`ValidationPipe(whitelist + transform + forbidUnknownValues)`。
- 全站内容风控：大部分用户可写入入口已走 `ContentModerationService.ensureReviewed`。
- 危险脚本拦截：在统一风控中增加了对 `<script>`、`iframe`、`javascript:`、`on*=` 等模式的拦截，命中直接拒绝。
- 鉴权与权限：管理端与用户私有写接口均要求鉴权（admin 额外校验管理员身份）。
- SQL 注入风险：数据访问主要通过 TypeORM 参数化查询或实体 API。

2) 本次补齐的缺口
- `requests.create` 增加 `riskConfirmed` 入参透传，并对申请快照字段执行风控审查与审计记录。
- `admin.updatePublicWelfareMessage` 改为 DTO 校验，避免无约束对象绕过全局参数校验。

3) 结论
- 当前后端用户输入主链路已具备“结构校验 + 内容风控 + 危险脚本拦截 + 审计留痕”的组合防护。
- 仍建议持续做灰盒渗透与依赖升级（SCA），作为长期机制。

### 4.5 可复制的 curl 验收命令

> 说明：以下命令可直接在 macOS zsh 执行；默认线上域名为 `https://cofounder.icu`。

```bash
BASE_URL="https://cofounder.icu"
```

#### A. 安全响应头检查

```bash
curl -sSI "$BASE_URL/" | grep -Ei 'strict-transport-security|x-content-type-options|x-frame-options|referrer-policy|permissions-policy|content-security-policy'
```

```bash
curl -sSI "$BASE_URL/api/health" | grep -Ei 'strict-transport-security|x-content-type-options|x-frame-options|referrer-policy|permissions-policy|content-security-policy'
```

```bash
curl -sSI "$BASE_URL/" | grep -Ei 'server:|x-powered-by'
```

#### B. 请求体大小限制检查（body-size）

```bash
perl -e 'print "{\"contact\":\"tester@example.com\",\"message\":\""; print "A" x 1200000; print "\"}"' > /tmp/cofounder-body-oversize.json
```

```bash
curl -i -X POST "$BASE_URL/api/public-welfare/messages" \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/cofounder-body-oversize.json
```

> 预期：返回 `413`（或等价 4xx 拒绝），表示网关/后端 body 限制生效。

#### C. XSS/注入拦截检查

```bash
curl -i -X POST "$BASE_URL/api/public-welfare/messages" \
  -H 'Content-Type: application/json' \
  --data '{"contact":"sec-test","message":"<script>alert(1)</script> xss probe"}'
```

> 预期：返回 `400`，并提示检测到高风险脚本或注入内容。

#### D. 健康检查最小化返回校验

```bash
curl -sS "$BASE_URL/api/health"
```

> 预期：仅包含 `ok` 与 `timestamp`。
