# 合伙造 - 产品需求文档 (PRD)

> 行业专家 × 程序员 = 合伙创业

---

## 一、产品概述

### 1.1 产品定位
**合伙造** 是一个连接行业专家与程序员的合伙创业匹配平台。

核心理念：**不是雇佣，是合伙；不谈工资，谈股权；先做MVP，再定分配。**

### 1.2 目标用户

| 用户类型 | 画像 | 核心诉求 |
|---------|------|---------|
| **项目方（行业专家）** | 在职副业/自由职业者，有行业知识和需求洞察，想做AI+垂类应用 | 找到靠谱的程序员合伙人，不用预付现金 |
| **程序员** | 被裁员/有危机感的开发者，想参与有前景的项目 | 找到好项目和懂行业的合伙人，用技术换股权 |

### 1.3 核心价值
- **解决信任问题**：陌生人通过共同完成MVP建立信任
- **降低启动门槛**：专家不需要预付资金，程序员以技术入股
- **快速验证匹配**：MVP阶段快速验证双方合作默契
- **渐进式信息披露**：降低填写阻力，在需要时才要求完善详细信息

### 1.4 账号规则
- **一个账号只能有一种身份**：注册时选择"项目方"或"程序员"，选定后不可更改
- 如需切换身份，需用另一个邮箱注册新账号

## 二、核心功能

### 2.1 功能清单（MVP版本）

| 优先级 | 功能模块 | 说明 |
|-------|---------|------|
| P0 | 用户登录 | 邮箱+一次性验证码，自动注册/登录 |
| P0 | 项目广场 | 程序员浏览项目列表 |
| P0 | 程序员广场 | 项目方浏览程序员列表 |
| P0 | 项目详情 | 展示项目完整信息 |
| P0 | 程序员详情 | 展示程序员完整信息 |
| P0 | 发起联系请求 | 双向：程序员申请项目 / 项目方邀请程序员 |
| P0 | 渐进式资料完善 | 第1步基础信息，第2步详细信息（查看联系方式前触发） |
| P1 | 我的请求 | 管理发出和收到的联系请求 |
| P1 | 个人中心 | 查看和编辑个人资料 |

## 三、用户流程

### 3.1 项目方流程
```
登录(选择项目方身份) 
    → 完善基础资料(项目简介+个人简介) 
    → 发布项目 / 浏览程序员广场
    → 收到程序员联系请求 或 主动邀请程序员
    → 想查看程序员联系方式时 → 触发完善详细资料
    → 完善详细资料后 → 双方互看联系方式
    → 开始合作
```

### 3.2 程序员流程
```
登录(选择程序员身份) 
    → 完善基础资料(项目经历+个人简介) 
    → 浏览项目广场
    → 对感兴趣的项目发送联系请求 或 收到项目方邀请
    → 想查看项目方联系方式时 → 触发完善详细资料
    → 完善详细资料后 → 双方互看联系方式
    → 开始合作
```


## 四、资料体系设计

### 4.1 设计原则
- **渐进式披露**：先要少量信息降低门槛，在用户有动力时再要求详细信息
- **对等交换**：双方都完善详细信息后，才能互相查看联系方式
- **信任建立**：详细信息帮助双方判断对方可靠性，减少被骗风险

## 六、信息可见性规则

### 6.1 信息分级

| 信息级别 | 可见范围 | 包含内容 |
|---------|---------|---------|
| 公开信息 | 所有用户 | 昵称、头像、行业/技术方向、经验年限、个人简介、项目经历简述 |
| 基础信息 | 登录用户 | 所在城市、当前状态、感兴趣行业 |
| 联系方式 | 双方都完善详细资料后 | 真实姓名、手机号、微信号 |
| 详细背景 | 双方都完善详细资料后 | 教育背景、工作经历、行业资源/技术能力详情 |

### 6.2 联系方式查看条件

```
条件1：请求已被接受（双向确认）
    +
条件2：本人已完善详细资料
    ↓
可查看对方联系方式

注：对方也需完善详细资料才能查看你的联系方式
```

## 八、风险与对策

| 风险 | 对策 |
|-----|------|
| 冷启动缺项目 | 创始团队先发布3-5个种子项目 |
| 冷启动缺程序员 | 在技术社区推广，吸引程序员入驻 |
| 项目方项目质量低 | 项目发布模板引导，必填项设计 |
| 匹配后失联 | 匹配后引导加微信，平台外沟通 |
| 用户不愿填详细资料 | 在有动力时触发（查看联系方式前），强调双向对等 |
| 虚假信息 | 收集详细信息增加造假成本，后续可考虑实名认证 |
